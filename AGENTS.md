# Architecture rules
- Documentation pages paginate company-scoped vehicle reads in groups of 25 and select one current CRLV for display without deleting history; licensing uses the vehicle UF, defaults only missing UF to SP, and never substitutes SP for an unavailable other-state calendar.
- Derive subscription billing notices from the current subscription's recurring linkage and cancellation flags, never its status alone; keep this presentation read-only and neutral when unavailable.
- Keep form validation in shared schema/helpers; similar-plate and company-name checks are advisory, while database triggers enforce new/changed plates and fuel driver ownership without rewriting legacy rows.
- Keep automatic overdue/settlement statuses in shared read-only presentation helpers; retain stored workflow statuses for editing and explicit actions to prevent reads from modifying historical records.
- Use the local calendar day, refreshed at midnight and on focus, for deadline-based presentation rules so today's deadlines never expire early.
- Enrich Dashboard summaries with company-scoped, paginated read queries using the same deadline helpers as list views; avoid database migrations or writes for presentation-only statuses.
- Derive preventive odometer deadlines through one shared helper using completed services, explicit next-service KM, open schedule targets and the company interval; use the registered current odometer consistently across maintenance and Dashboard.
- Dashboard document counts mirror Documentation's active-entity scope and licensing calendar, deduplicating licensing/CRLV per vehicle and CNH per driver; driver cards share active-status and CNH helpers with Drivers, while month costs use bounded company-scoped reads and the same categories for previous-month comparisons.
- The authenticated Alerts page aggregates company-scoped read-only deadline and insurance calculations; uninsured vehicles follow Insurance's active policies, unremoved links, unrevoked manual matches and extracted plate matches, with no synchronization writes during reads.
- Fuel receipt SELECT/INSERT/UPDATE policies share a caller-bound, security-definer authorization helper with a pinned search path; station paths must match persisted station/authorization relationships, and UPDATE checks both source and destination to prevent cross-company moves.- Critical checklist failures open maintenance requests only through a database trigger linked by checklist run, and "restricted vehicle" is derived read-only from open linked requests, so clients never duplicate requests.
- Fuel anomaly explanations, tire alerts and trip finance (balance, cost per km, result) are computed read-only in shared helpers; only explicit user actions (reconciliation, measurements, movements) write records.
- Agent API authenticates SHA-256 key hashes and uses the service role only inside its edge function; every read/write is company-scoped, agent writes carry `source='agente'`, runtime heartbeats stay out of the action log, and no action creates or settles payments so the trusted local motor cannot cross tenants or alter financial state.
